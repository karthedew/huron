Roadmap

The greenfield build: phases with mechanical gates, sequenced so every phase ships something a scientist or operator can use. Nothing here amends or extends any earlier plan — this is the plan.

1. Greenfield stance

Huron starts clean. No API compatibility with any earlier prototype, no data migration, no inherited schema, no deference to prior decisions. Existing code and documents are reference material at most; any idea reused from them must re-justify itself against this design record. Practically:

  • A fresh domain model, fresh migrations from revision zero, and a fresh OpenAPI contract — nothing is shaped to accommodate what already exists.
  • Prototype endpoints, schemas, and plans are retired outright. No dual-running, no compatibility shims, no migration tooling.
  • Repository hygiene from day one: the three-surface layout below, with import-linter enforcing every boundary in it — no package imports a sibling package, no service imports a sibling service, and catalog/ and rbac/ know nothing of FastAPI, SQLAlchemy, storage SDKs, or LanceDB; a task is done when its gate passes in CI, not when the code is written; any change to a decision or invariant updates this design directory in the same PR.

The dependency rule is one-way and mechanical: service → pkg → schema. Never the reverse and never sideways. A package that needs another package's capability does not import it — it declares a typing.Protocol describing what it needs, and a service passes in a conforming object. Because Protocol conformance is structural, the implementing package does not import the declaring one either, which is what lets pkg/* be genuinely independent rather than merely tidy. mypy checks conformance at the wiring site, where the concrete object meets the Protocol.

Four import-linter contracts hold this in place, and all four are checked in CI: a layers contract for service → pkg → schema; an independence contract across the eleven packages; an independence contract across the twelve services; and a forbidden contract keeping web frameworks, database drivers and storage SDKs out of catalog/ and rbac/. Data-modeling and validation libraries are deliberately not on that forbidden list: schema/ is built on them, and catalog/ validates against schema/ rather than restating formats.

Two consequences worth stating, because they are the ones that bite in review. Cross-cutting concerns do not get a shared import: a package that wants to log uses the standard library, and the service configures telemetry/ to capture it. And behavior two services both want becomes a package — never an import of the sibling that happens to have it already.

PhaseDeliversGate (mechanical)
P0 — Bootstrap Repository skeleton and dependency groups; tooling (ruff, mypy strict across pkg/ and schema/, import-linter, pytest markers); compose stack (PostgreSQL, MinIO for derived layers, a local volume standing in for NFS); settings module whose startup refusals are tested (dev-auth outside development, invalid classification vocabulary); CI with lint → unit → contract → integration stages. Green CI on the empty tree; a deliberately added import fastapi in pkg/catalog/, an import of one package from another, and an import of one service from another each fail their contract; the compose stack boots and bootstraps buckets and volumes from a clean checkout.
P1 — Foundations Domain model for the five-level hierarchy in pkg/catalog/; catalog/paths.py (construction + parsing, per-resource slug limits); manifest/JCS module with the full rejection matrix; UUIDv7; PosixRawStore in pkg/rawstore/; migrations (hierarchy, role_bindings, api_keys, audit with pre-created partitions, outbox); RoleBindingAuthorizer with discovery gating; API-key + OIDC resolvers; org/project/dataset CRUD with generation documents; release tags; browse with keyset pagination; OpenAPI published, TS + Python client cores generated. Create org → project → dataset via HTTP; generation docs and CURRENT.json at the exact documented paths; a release tag resolves to one revision and a second write of the same tag is 409 TAG_EXISTS; slug-change attempts 409; API-key auth round-trip; a principal scoped to project A gets full-size pages with zero rows from B and no evidence of B in counts or cursors; import-linter green.
P2 — Raw ingest & commit Session state machine (dataset-scoped lock), upload plan with hardlink dedup, streaming in-flight hashing, the POSIX commit protocol (staging → fsync → atomic rename), sealing, download capabilities, INDEX.json. Round trip: a tree with NFC/NFD pairs, a zero-byte file, 8-level nesting, and a 9 GiB file ingests and downloads byte-identically. Crash matrix: kill after every protocol step; staging crashes invisible and swept; post-rename crash imported as an orphan with no duplicate on retry. Resume re-sends only incomplete files. Two racing BeginIngest calls: exactly one wins; 100 sequential ingests number 1..100 gap-free. Replayed commit returns the same revision. Dedup: 1 changed file of 500 uploads exactly 1; the other 499 hardlink; the new revision is independently complete. Every path-rejection rule produces its documented error code.
P3 — Integrity services Staging-only sweeper with fraction guard and dry-run; reconciler implementing the findings table plus seal/hardlink verification; lakectl rebuild --from-storage. Drop the database, apply migrations, rebuild from the filesystem alone: identical inventory of orgs, projects, datasets, revisions, release tags, amendments — with a purged and an expired revision present and reported lawful, not DEGRADED.
P4 — Search projection Outbox consumer (single writer), LanceDB datasets + revisions + snapshots + products tables covering all four layers (Tantivy FTS, scalar filters, embedding column reserved), /search with pre-ranking authorization filter and PostgreSQL re-check, lag reporting, pointer-flip rebuild. A user with access only to project A searching a term matching only project B gets zero results, correct pagination, no leaked facets. Stop the worker and delete the tables: browse, ingest, and commit all work; /search returns 503; rebuild restores it.
P5 — Governance Steward amendments with the field allow-list and single fold implementation; reclassification as its own audited permission; two-person purge; retention: per-category TTL, pins, legal holds, EXPIRED markers; science-profile registry (immutable published versions, mirrored to storage); quota enforcement at BeginIngest. Every forbidden amendment field rejected; fold correct across 3 chained amendments; two-person purge enforced by the database, idempotent on re-run, reported lawful by the reconciler; expiry removes only TTL-category files, only after Silver exists, writes the marker, honors holds; the consequence text appears in the API response that sets the policy.
P6 — Bronze Jobs table + runners, the MCNP extractor as the reference profile, Icechunk repos on RGW, candidate → validated → published snapshot flow, validation evidence, catalog registry, LanceDB layer flags. Upload run-0042 ⇒ a published Bronze snapshot whose provenance names the exact revision and extractor digest; a corrupted output ⇒ FAILED with structured findings and nothing published; rebuilding the same revision is idempotent.
P7 — Silver Canonical contracts, the MCNP canonicalizer, the per-dataset Silver repo, contract-driven concatenation resolved through the catalog, per-run lineage, silver validations. Three datasets declaring one contract concatenate along run into a single particle_flux(run, energy, x, y, z) view; a fourth declaring a different contract version is excluded from that set by the catalog; a corrected revision of run-0042 republishes only run-0042's repo and leaves the other three repos byte-identical; every prior snapshot still opens identically after all of it.
P8 — Client GA & grants Grant endpoints with STS vending (+ proxy fallback), the huron package (open/upload/search), credential renewal loop, typed errors, the scientist CLI. open_dataset on an HPC login node with only an API key reaches first bytes in < 5 s; a revoked role stops reads within one credential TTL; grant-scope escape attempts fail at the store (policy test, not application test); a pinned snapshot reproduces byte-identically after a subsequent append.
UI-α / UI-β α (after P4): the Databricks-shaped shell (left rail + catalog explorer), browse, search, dataset/revision pages, Grafana-shaped permissions tabs, API-key management, read-only admin. β (after P8): validation evidence, lineage graph, retention panels, steward queues, the publication flow. The generated TypeScript client compiles in CI against every API change; E2E smoke against the compose stack.
P9 — Gold Products, versions, pinned derivation records, product runner, validation gating, publication, staleness propagation, cross-project inputs with redacted lineage, Iceberg materialization for tabular products. The MCNP thread end-to-end: flux → dose published with lineage G021 ← S117+S031 ← B182 ← rev-1; an upstream correction marks it STALE with the reason; recompute produces 1.0.1 pinned to the successors; the derivation record alone re-executes to a bit-identical G021 (invariant K).
P10 — Polaris Polaris deployment, sync worker, namespace/table mapping, grant projection, /polaris/credentials, nightly converge. A published tabular product is queryable from Spark and DuckDB via Polaris within one sync cycle; a WITHDRAWN version disappears; a grant not derivable from Huron bindings is detected and alerted; Polaris wiped ⇒ lakectl polaris resync reconverges from the catalog.

3. Sequencing rationale

  • P2 before everything derived: the evidence tier must be trustworthy (crash matrix, rebuild) before any pipeline consumes it. P3 follows immediately because the reconciler is what makes P2's crash-consistency gate fully checkable.
  • P4 early: search makes the lake usable to humans before derived layers exist, and the outbox/projection machinery it builds is the same event backbone P6–P9 consume.
  • P8 immediately after P7: the first Silver snapshot with no ergonomic way to open it would stall adoption; the grant flow is the product moment.
  • P10 last: Polaris mirrors published tabular Gold — there is nothing to mirror before P9, and nothing blocks on it (its failure posture is "degrade external engines only").
  • Cross-cutting, never a phase: FIPS smoke and the OpenAPI-contract check run from P0 onward; instrumentation (unchanged-byte ratio, layer sizes per project, ingest durations, projection lag, grant issuance rates) ships with the code that emits it, because the full-copy-vs-delta and TTL-length decisions get revisited with data, not opinion.

4. First moves

  1. Stand up the fresh repository per §1 — layout, tooling, compose, CI (P0).
  2. Build the pure core first: pkg/catalog/ids.py, pkg/catalog/paths.py, pkg/catalog/manifest.py with their property tests — everything else leans on them.
  3. Prototype in parallel, throwaway-labeled: an Icechunk repo on MinIO exercised through xarray.open_zarr on a read-only session, and an RGW STS AssumeRole-with-session-policy probe. These are the two external assumptions P6 and P8 lean on hardest; confirm the deployed Ceph's STS behavior before P8 planning, and the proxy fallback covers the worst case.
  4. Write the MCNP science profile alongside P1, not after P5 — it is the reference case every layer document uses, and drafting it early keeps the profile schema honest.
