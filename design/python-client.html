Python Client & Aether

The huron package: the scientist-facing door. Opens any layer as a lazy Xarray dataset, uploads revisions, publishes products — with an API key required for every call and reproducibility pinning built in.

1. Package shape

huron/
  _core/           generated from OpenAPI (openapi/v1.json) — never hand-edited
  client.py        HuronClient: auth, retries, idempotency keys, pagination
  open.py          open_dataset / open_snapshot / open_product  → xarray
  ingest.py        revision upload: manifest build, streaming, resume
  layers.py        manual bronze/silver intake: `huron bronze upload` — NetCDF/HDF5/
                   zipped-Zarr in, provenance assertion (raw link | external), job watch
  products.py      publish, versions, staleness queries
  search.py        search() with typed filters
  cli/             `huron` command (thin wrapper over the same client)

Dependencies for the read path: icechunk, zarr, xarray, httpx. The generated core keeps client and server contracts locked together — a breaking API change fails the client build in CI.

2. Authentication

export HURON_API_KEY=hk_01993ab2…_s3cr3t          # precedence: argument >
client = huron.connect()                           # env var > ~/.config/huron/config.toml
  • The API key is required: no anonymous mode, no ambient site credentials. Keys are created in the UI or via huron auth create-key; the client refuses to start without one and says exactly where to get one.
  • The client never sees long-lived storage credentials — only grant-scoped, expiring STS credentials fetched on demand (§3).
  • huron auth whoami prints principal, roles, and key scopes — the first debugging step for every permission question.

3. The open path (the Xarray front door)

import huron

ds = huron.open_dataset(
    "nuclear-engineering/huron-shielding-study/reactor-shielding-sweep",
    layer="silver",                 # "bronze" | "silver"; default "silver"
)
dose = huron.open_product("shielding-dose-response", version="1.0.0")
ds117 = huron.open_snapshot("S117")           # exact pin, any layer

What happens underneath, and where RBAC bites:

open_dataset(path, layer)
  1. resolve: GET /datasets?slug-path=…        → 404 if not discoverable   [dataset.discover]
  2. grant:   POST /data-access/grants          → 403 if layer not readable [dataset.read_{layer}]
       response pins snapshot_id (e.g. S117) and returns scoped read-only
       STS credentials for the one repo prefix, TTL ≤ 1 h
  3. open:    icechunk.Repository(uri, credentials) → readonly_session(snapshot=S117)
  4. wrap:    xarray.open_zarr(session.store, …)    → lazy dataset; chunk reads
              go client → object store directly, never through FastAPI
  5. renew:   a background refresher calls grants/{id}:renew before expiry and
              swaps credentials in place; renewal re-authorizes, so a revoked
              role stops reads within one TTL
  • Reproducibility is ambient: every returned dataset carries ds.attrs["huron"] = {dataset id, layer, snapshot id, grant id, opened_at}. Pinning is one attribute away: huron.open_snapshot(ds.attrs["huron"]["snapshot_id"]) reproduces the exact view forever, and the recommended pattern in papers/notebooks is the snapshot form.
  • Staleness surfacing: opening a STALE product version warns with the reason and the successor version; opening a non-latest Silver snapshot notes the newer one. Warnings, never refusals — reproducibility outranks tidiness.
  • Restricted transport fallback: where compute nodes cannot reach the object store, the grant response returns mode: proxy and the same code path reads chunks through the API at reduced throughput. Client code does not change.

Aether

Aether consumes exactly this surface — its huron.open_dataset() results are plain Xarray objects, so aether.integrate(silver["particle_flux"] * coefficients["dose_coefficient"], dim="energy") needs nothing Huron-specific. For transformations that should become Gold, Aether jobs run under the submitting user's key (or a project service account), and the derivation submission below is the hand-off point. The one rule: an Aether job that will be published must take its inputs from grant-opened snapshots, because the publication pins whatever the platform resolved — inputs smuggled in from local files fail validation's coverage checks.

4. Upload path

(Step-by-step journey context, including the manual bronze intake this section's verbs serve: Scientist Workflows.)

huron upload ./run-0042 \
  --dataset nuclear-engineering/modeling-simulation/run-0042 \
  --infer --confirm
  • The client walks the tree, applies the same NFC normalization and rejection rules as the server (shared test vectors keep them locked), hashes every file, and calls BeginIngest with the manifest; required, Pydantic-validated metadata accompanies commit.
  • --infer shows what the profile extractor found (MCNP version, NPS, tallies, completion state…); the human confirms only the assertions Huron cannot infer (campaign, purpose, quality state).
  • Uploads stream every submitted file with bounded concurrency from the UploadPlan; interrupted transfers resume via completed_parts; heartbeats run while any transfer is in flight.
  • Programmatic form: dataset.upload(source=path, metadata={…}) returns the committed revision; a correction is the same call again — it simply commits revision n+1, with reason= recorded in the audit trail.
  • Pinning. open_dataset("…/run-0042@revision-1") resolves to one immutable revision; bare …/run-0042 resolves to the latest committed revision and is therefore not reproducible — the client warns when an un-pinned reference is used inside a product derivation.

5. Product publication

version = client.products.submit_version(
    product="shielding-dose-response", semver="1.0.0",
    inputs=[Input(dataset="…/reactor-shielding-sweep", layer="silver"),
            Input(dataset="reference-data/icrp/icrp-flux-to-dose-coefficients",
                  layer="silver")],
    transform=Transform(image="registry/…/flux-to-dose@sha256:3e4f…",
                        parameters={"conversion_coefficients": "icrp-116"}),
    validation="dose-product-v1")
version.wait()                      # CANDIDATE → validated
client.products.publish(version)    # requires project_admin

The client's role ends at submission — the platform pins snapshots, runs the container, and gates publication (Gold §4). version.evidence exposes the validation results for review before publishing.

6. Errors, retries, versioning

  • Problem-document codes map to typed exceptions (huron.errors.DatasetLocked, TagExists, GrantExpired, ValidationFailed…); control-flow codes are stable API contract.
  • Idempotent retries with backoff on 5xx/timeouts; mutating calls auto-generate Idempotency-Keys so a retried commit can never double-publish.
  • The client sends X-Huron-Client: python/{version}; the API's minimum-supported check gives a clear upgrade error instead of a contract mismatch.
  • Search: huron.search("absorbed dose", kind="product", project="huron-shielding-study") — surfaces projection_lag_seconds on the result object and raises SearchUnavailable on 503 (never silently degrades to a browse scan; the ban is client-side too).
