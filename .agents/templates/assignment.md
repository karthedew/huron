# Self-contained worker assignment

- Phase/task and plan path; role and attempt (review N of at most 3).
- Explicit profile: medium for ordinary code/fixes/reviews, maximum when explicitly
  selected. Final complete qualification requires maximum with verification/review.
  Preparatory is only for non-code preparation. Record requested/recorded profile,
  configured effort, observed model and provider acceptance not-proven separately.
- Explicit activity (code/discovery/planning/prototype/review) and exact read/write
  claims; canonical resource dictionary mapping each label to files/services/artifacts.
  Include subject ownership and all shared check-output claims (build:agent-tools for
  `.agents` npm tests). Code excludes ALL work; non-code must be nonconflicting.
  Claims are cooperative coordination, not a sandbox; uncertain scope uses *:write.
- Objective, current verified context, durable decisions and prerequisite results.
- Exact ownership: allowed files/symbols, exclusions, existing dirty/untracked work.
- Full acceptance criteria, interface signatures/examples and explicit deletions.
- Prototype question, result, evidence and limitations (copy essential conclusions).
- Required skills, each named with its approved source path from `.agents/README.md`.
- Resolved runtime/model settings, child progress delivery and evidence destination.
- Actual loaded schema/restart status; per-child start/last-progress/observed times,
  progress age and separate actual-last-response terminal evidence. No credentials
  in progress. Recovery owner: no manual resume, classification escalation, automatic
  replay or stale-lock stealing; human authorization plus child/process reconciliation.
- Paste the complete applicable gate from `../workflows/verification.md`, resolved
  with commands/cwd/prerequisites/pass criteria, and its testing standard verbatim.
- Paste the progress contract from `../workflows/orchestration.md` verbatim.
- Include baseline outputs/findings; for fixes include every review finding; for
  review include implementer summary as a lead, not proof.

Worker rules: read the full plan and inspect actual files before working. Do not
delegate. Preserve unrelated user work/data. No backward compatibility unless
explicitly required. Do not commit, branch, push, create issues, promote prototypes
or change permissions. Remove only obsolete owned code/tests. No auto-revert on
failure. If scope or a decision is insufficient, report BLOCKED with evidence.

Review/baseline/discovery rules: no edits (including through shell), other than
normal ignored test/build artifacts. Independently inspect the actual tree and
rerun the full applicable gate. Shell access is not a read-only sandbox.

Return: files changed/deleted (or inspected), acceptance evidence, exact command
results/log paths, findings with locations/corrections, baseline attribution and
remaining blockers. Reviews return PASS / FAIL / BLOCKED; self-checks are not
independent review. Review 3 classifies each remaining issue as a fixable defect
or plan defect. Report required config restart where applicable.
