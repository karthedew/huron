REST API

FastAPI, /api/v1. Conventions, uniform across the surface: UUIDv7 IDs, RFC 3339 timestamps, versioned keyset cursors, application/problem+json errors with stable codes, If-Match preconditions on the resource version, Idempotency-Key on mutating posts. An Idempotency-Key is scoped to the acting principal, replays the original response for 24 hours, and a reuse of the same key with a different request is 409 IDEMPOTENCY_KEY_REUSED. OpenAPI is the published contract and generates the TypeScript and Python client cores; breaking changes fail CI.

Current implementation seam: this design includes future routes; the Core map and UML atlases describe the migrated source. ApiRuntime holds public RawRuntime construction and wires Security authentication from ports, clocks and plain values. Dependencies construct actor-bound Catalog, Raw and Security operations. Early guards use public inspection/authorization before body work; complete domain operations independently enforce authority. Routes retain HTTP parsing, streaming, cookies/CSRF, redirects and error serialization. Adapter composition/lifetime belongs to the application; wiring capabilities prove the adapters satisfy the narrow consumer ports. Migration verification is recorded in the roadmap.

Simple hierarchy, policy and service-account handlers return typed Core results; explicit FastAPI response_model declarations validate and filter them into the existing named public views. Internal fields such as hierarchy generation stay off the wire. Pagination, credential issuance and streaming retain their transport-specific representations.

Browse endpoints are PostgreSQL-only, filterable by structural columns, cursor-paginated, with the authorization predicate ahead of LIMIT. No free-text parameters — that is /search.

The named PatchOrganization, PatchProject and PatchDataset bodies inherit their optional fields and to_change(expected_version) translation from the application schema's DescriptionPatch. Omitted or null fields retain their values; empty strings replace them, and extra fields remain ignored. Handlers parse If-Match after their discovery/capability guards. Core rejects a changed slug before checking a stale version, checks the version even on a no-op, and performs the authorized update. The common input base is not a separate OpenAPI component.

5. Data-access grants

The endpoint family the Python client is built on. The API authorizes, resolves the snapshot, and vends scoped storage credentials; array bytes never transit FastAPI.

POST /data-access/grants
{"dataset": "nuclear-engineering/huron-shielding-study/reactor-shielding-sweep",
 "layer": "silver"}                        # or {"snapshot_id": "S117"}
                                           # or {"product": "…", "version": "1.0.0"}

201 →
{"grant_id": "01993a…",
 "repo": {"kind": "icechunk",
          "uri": "s3://huron-silver/orgs/nuclear-engineering--…/…/repo/",
          "endpoint": "https://rgw.site.example"},
 "snapshot_id": "S117",                    # resolved & pinned at issue time
 "tag": "silver/S117",
 "credentials": {"access_key_id": "…", "secret_access_key": "…",
                 "session_token": "…", "expires_at": "2026-08-23T20:12:00Z"},
 "mode": "read-only"}

POST /data-access/grants/{id}:renew        # re-authorizes, returns fresh credentials
GET  /data-access/grants                   # own active grants (audit/debug)
  • Authorization is checked at issue and at every renewal — revoking a role strands the reader within one credential TTL (≤ 1 h).
  • layer: "silver" resolves to the latest published snapshot and returns its ID, so even "give me latest" is reproducible after the fact.
  • Credentials come from the gateway's STS endpoint (AssumeRole with an inline session policy scoped to the one repo prefix, read-only) — gateway-conditional per the S3-portability boundary. The vending backend is a port; a deployment without STS falls back to API-proxied chunk reads (GET /data-access/proxy/…) at reduced throughput — same client code path, degraded transport.
  • Every grant is audited: who, which snapshot, which prefix, when, from where.
