Reading the relationships

Object ownership

  • RawstoreService.catalog → Catalog: injected, one per service.
  • RawstoreService.fs ◆→ Filesystem: created and retained by the service.
  • RawstoreService → StreamingFile: creates a temporary writer per file transfer; no stored writer field.
  • StreamingFile.spec → FileSpec: retains one file declaration. Its constructor uses Filesystem and Ingest to derive paths without retaining those objects.
  • Ingest.dataset → DatasetRef and Ingest.files → FileSpec: references to frozen records, with no exclusive ownership implied.

Data dependencies

  • Catalog looks up DatasetRef, reserves and claims Ingest, records FileSpec receipts, and publishes Revision.
  • Filesystem accepts DatasetRef and Ingest for layout, validation, and finalization.
  • RawstoreService.stage() consumes file declarations and returns Ingest; ingest() returns Revision.
  • Revision carries identifiers and a relative path, rather than retaining an Ingest object.

Upload lifecycle

  1. stage(): initialize storage, reserve ingest, create staging workspace.
  2. write_file(): claim session, stream bounded blocks, verify size/hash, record receipt.
  3. ingest(): claim/seal, validate, rename, mark storage-ready, publish through the catalog.

The on-disk COMMITTED marker means storage validation succeeded. Catalog publication is the visibility boundary. Authorization and a persistent PostgreSQL catalog are external to this example.

Module-level helpers and notation

These are functions, not class methods, so they sit outside the UML class boxes:

  • relative_path(value) → PurePosixPath — canonical relative path validation.
  • «async» finish_awaitable(operation) → T — drain an owned task before propagating cancellation.
  • «async» finish_thread(function, *args) → T — run and drain blocking I/O off the event loop.
  • fsync_directory(path) → None — sync directory metadata.
  • ensure_directory(path) → None — create one directory and sync its parent.
  • ensure_tree(base, relative) → Path — create a relative directory tree.
  • sha256_file(path) → str — hash a file using bounded reads.
  • manifest_bytes(ingest) → bytes — deterministic manifest serialization.
  • atomic_document(path, contents) → None — idempotent sidecar installation.

BUFFER_SIZE = 4 × 1024 × 1024 bytes. T is a type variable. AsyncCM[Ingest] abbreviates AbstractAsyncContextManager[Ingest]; Plan abbreviates Literal["NEW_DATASET", "NEW_REVISION"]. “Binary writer” and “SHA-256 hash” describe inferred runtime objects, not source annotations.
